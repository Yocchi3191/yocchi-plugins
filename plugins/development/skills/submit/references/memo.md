# ADRメモと作業メモの扱い

## ADRメモ

- `design` が残した一時ファイル。PR本文の `## 設計判断` に展開したあと、削除する
- 見つかったら内容を読み込む。PR本文の `<ADR>` 欄にそのまま入れる（`<ADR>` 欄の規則はテンプレートの注釈に従う）
- コミットに含めない。stageのpathspecで除外する（`':(top,exclude)<adr-path>'`）

## 作業メモ（`impl` が追記したもの）

`impl` が作業中に追記した、設計のアイデアや判断、更新したREQの記録。このskillは置き場を知らないので、次の順で決める。

- プロジェクトのCLAUDE.mdに作業メモの置き場が書いてあれば、聞かずにそれを使う
- 書いていなければ、ユーザーに置き場を聞く。「不要」と答えられたら、作業メモ無しとして扱う
- 置き場にファイルが無い、または読めなければ、作業メモ無しとして扱う（エラーではない）

読み込んだ内容は、Step 4でPR本文を埋める材料に使う（`<SUMMARY>`・`<STRUCTURE>`・`<FLOW>`・`<ADR>` など）。

- 置き場が複数の作業で共有されていることがある。このブランチの作業に関する記述だけを使う
- `impl` が書いた、行頭にブランチ名の付いたログ行（`decision:`・`dead-end:`・`next:`）は、このブランチ名の行だけを使う
- `next:` と `dead-end:` は再開用の記録なので、PR本文には貼らない。材料にするのは `decision:` だけ
- 作業メモの文面をそのまま貼らず、テンプレートの該当欄に合う形に整理する（ADRメモは対象外）
- 作業メモは削除しない。コミットするかどうかも判断しない（`.gitignore` などリポジトリ側の管理に任せる）。`git add -A` で作業メモが含まれうるのは、その方針による
