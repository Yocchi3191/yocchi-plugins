# developmentプラグイン レビューSkill レビュー規約

PRは、問題に対する「問題解決」の実装である。
1つのPRには1つの「問題解決」と、「問題解決」を成り立たせるための軽微な調整だけがあるべき。

# 品質基準に満たないPR

PRの「問題解決」が1つでない

# 変更量の上限

品質基準を満たすPRであっても、変更量が非常に多い場合、レビュー負荷の高い読みにくいPRになっている。
そのような場合は「問題解決」自体のスコープが広く、さらに詳細な「問題解決」に分割可能かを検討する。
分割可能と判断した場合は、PRのstacked PR化を促す。

例) 機能Xの実装PRは、モジュールA, B, Cの実装PRに分割可能なため、A, B, Cでそれぞれ分けたStacked PRに分割することを促す

分割を促すかどうかの指標は、PRの行数および文字数である。

```
- コード: 変更行数200行以下
- 文章: 文字数400字以下
```

上記はあくまで指標である。目的はPRを読みやすい状態に保つことであり、機械的な変更で、全差分を読まなくてもよい変更などはこの限りではない。

### 行数・文字数をカウントしないもの

特性上変更行数が多くなりやすい、または減らすことで実害があるようなファイルや、ツール側で自動的に生成されるファイルは指標の判定対象から除外する。

- テスト
- バイナリファイル
- フレームワーク・ミドルウェアが自動生成したファイル(ex. `.lock`, `.meta`)

## 備考

PRを読んでいて判断に困る点があれば、レビューを中断して、その点をコメントで質問する。 担当者からの回答が得られ次第、再度PRの評価を再開する。
