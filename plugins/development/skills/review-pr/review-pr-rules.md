# developmentプラグイン レビューSkill レビュー規約

PRレビューでは「よいPR」のみをレビューし、そうでないものは「よいPR」にするための案内を出す。

基本的なPRには、主に以下の要素が含まれる

1. 問題解決
2. 問題解決のための調整

「問題解決」とは、そのPRの変更が実装しようとしている機能や修正を指す

## 「よいPR」の条件

PRレビューを依頼された場合は、対象PRの本文、issueをもとにdiffを1～2に仕分ける。
以下の条件に該当すれば「よいPR」とみなす

1. PRに含まれる「問題解決」が1つだけである
2. レビューしやすい差分量である。または機械的に適用された変更で、すべて読まなくても差分が予測可能である

### 「レビューしやすい差分量」の指標

- コード: 変更行数200行程度
- 文章: 文字数400字程度
  - claudeのSKILL.mdやこのドキュメントのような参考資料も文章と見なす

上記はあくまで指標であり、条件2の「機械的な変更」で、全差分を読まなくてもよい変更などはこの限りではない。

### 行数・文字数をカウントしないもの

- テスト
- バイナリファイル
- フレームワーク・ミドルウェアが自動生成したファイル(ex. `.lock`, `.meta`)

## 備考

PRを読んでいて判断に困る点があれば、仕分け・評価を中断して、その点をコメントで質問する。 担当者からの回答が得られ次第、再度PRの評価を再開する。
