# developmentプラグイン レビューSkill レビュー規約

PRは、問題に対する「問題解決」の実装である。
1つのPRには1つの「問題解決」と、「問題解決」を成り立たせるための軽微な調整だけがあるべき。

# 品質基準に満たないPR

「問題解決」が複数あるPRは、品質基準を満たさない。

# 変更量の目安

変更量が多いPRは、レビュー負荷が高く読みにくい。「問題解決」が複数混ざっている、またはスコープが広すぎる疑いがある。
そのような場合は、さらに詳細な「問題解決」に分割可能かを検討する。
分割可能と判断した場合は、PRのstacked PR化を促す。

例) 機能Xの実装PRは、モジュールA, B, Cの実装PRに分割可能なため、A, B, Cでそれぞれ分けたstacked PRに分割することを促す

分割を検討するかどうかの目安は、PRの行数および文字数である。

```
- コード: 変更行数200行程度
- 文章: 文字数400字程度
```

上記はあくまで目安であり、超えただけで不合格にはしない。目的はPRを読みやすい状態に保つことであり、機械的な変更で、全差分を読まなくてもよい変更などはこの限りではない。

## 行数・文字数をカウントしないもの

次のファイルは、目安の判定対象から除外する。

- テスト
- バイナリファイル
- フレームワーク・ミドルウェアが自動生成したファイル(ex. `.lock`, `.meta`)

## 備考

PRを読んでいて判断に困る点があれば、レビューを中断して、その点をコメントで質問する。 担当者からの回答が得られ次第、再度PRの評価を再開する。
