# REQを更新するとき（Redで、テストが正しく、REQが足りなかった場合）

Redの失敗理由がREQの意図と違い、調べた結果、テストが正しくて、REQの調査が足りていなかったと分かったときの手順。

1. 更新後のREQの文を、人間に見せ、承認を得る。**承認を得る前に反映しない**
2. 承認されたら、issue本文のREQを更新する。本文はバッククォートや引用符を含みうるので、シェルに埋め込まず、リポジトリ外の一時ディレクトリに書き出して渡し、反映したら一時ファイルを削除する

```bash
gh issue edit <番号> --body-file <更新した本文を書いた一時ファイル>
```

3. 反映に失敗したら、失敗内容を伝え、更新後の文を提示して、手動での反映を頼む
4. 更新したREQ番号と理由を、作業メモに `decision:` として残す。`submit` がPR本文に使い、「REQ-<n>を直した」とレビューで分かるようにするため
5. 更新後は、Redの失敗理由が新しいREQの意図と合っていることを確認してから、Greenへ進む
