# 差分の書き出しと大きさの測り方（Step 4・6）

## 差分とコミットログの書き出し

書き出し先は `.git` の中の決まったパスで、毎回上書きする（作業ツリーを汚さず、ファイルも溜まらない）。

```bash
set -e
out="$(git rev-parse --absolute-git-dir)/development-review"
mkdir -p "$out"
git diff --no-color --no-ext-diff -M <BASE_SHA>..<HEAD_SHA> > "$out/diff.patch"
git log <BASE_SHA>..<HEAD_SHA> > "$out/log.txt"
test -s "$out/diff.patch"
echo "$out"
```

どれかが失敗した、または差分が空なら、レビュー役を起動せず、理由を伝えて停止する。

## 差分の大きさ

PRの大きさの上限と、その根拠・測り方は、プラグインのルートの `review-rules.md` の「PRの大きさの上限」に書いてある。この節を最後まで読み、そこに書かれた方法で `<BASE_SHA>` から `<HEAD_SHA>` までの差分を測り、上限と比べる。**上限の値と測り方はここに書き写さない**（`split-pr` も同じ規約で判定するので、定義を1か所に保つため）。

測る前に、差分のファイル一覧から、規約の「テストは数えない」に従って、数えないテストのファイルを決める。

```bash
git -c core.quotepath=false diff --name-status -M <BASE_SHA>..<HEAD_SHA>
```

- `core.quotepath=false` を付ける。付けないと、日本語のパスが8進表記の引用符つきで出力され、除外が効かない
- リネーム（`R` で始まる行）をテストとして数えないときは、新旧両方のパスを渡す。新しいパスだけだと、リネームと判定されず、旧パスの削除として全行が数えられる
- 数えなかったファイルと、判断できなかったファイルは控えておき、報告に添える

スクリプトが失敗したら、同じコマンドを2回までリトライする。それでも失敗したら、大きさを測れなかったことを報告に添え、中身のレビューは続ける。`.gitattributes` はチェックアウト中のものが読まれる（Step 3でチェックアウトが `HEAD_SHA` と一致することは確認済み）。

結果（行数・バイト数・上限超過か）を控える。上限を超えていても停止しない（分割を見送ると判断された場合でも、中身のレビューを受けずに進むことが無いようにするため）。

## 報告に添える行

上限の値は `review-rules.md` から埋める。

```
差分の大きさ: <行数>行・<バイト数>バイト（上限: <規約の行数>行・<規約のバイト数>バイト）
```

テストのファイルを数えなかった場合は、その直後に1行添える。判断できずに数えたファイルがあれば、それも並べ、テストかどうかをユーザーに聞く。

```
数えなかったテスト: <ファイルの数>件（<パスを並べる>）
```

スクリプトが失敗していた場合は、「数えなかったテスト」の行は添えず、大きさの1行の代わりに「差分の大きさを測れなかった」とその理由（エラー出力）を添える。
