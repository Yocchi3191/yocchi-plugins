# レビュー開始前の確認

上から順に確認する。
「早期終了」になったら、理由を伝えてレビューを終える。
どれも早期終了にならなければ続行し、状況（ローカル／PR1回目／PR2回目）を決めておく。

# 1. 引数の確認

このSkillの引数の受け取り方は以下

1. 引数なし
2. PR番号(ex.PR#123なら 123)

引数がPR番号でない、または多すぎる等で不正なら、レビューをスキップする旨を伝えて早期終了する。

# 2. レビュー回数の数え方（PRのみ）

- PRのコメントから、最新の `<!-- development:review count:N -->` を探す（`gh pr view <PR番号> --json comments`）。
- 見つからなければ、現在のレビュー回数を1回目、あればN+1回目にする。
- ローカルのレビューでは回数を記録しない。

# 3. レビュー回数の上限（PRのみ）

今回のレビュー回数（手順2で決めた回数）が3以上なら、レビュー上限のためスキップする旨を伝えて早期終了する。

# 4. ブランチの確認

`--fix` は作業ツリーを書き換える。

- PR: `gh pr view <PR番号> --json headRefName -q .headRefName` が今のブランチと違えば、切り替えてよいか人間に聞く。断られたら早期終了する。
- ローカル: `git branch --show-current` が空（detached HEAD）、または今いるブランチがデフォルトブランチそのものなら、レビュー対象が無いので、その旨を伝えて早期終了する。デフォルトブランチ名は `gh repo view --json defaultBranchRef -q .defaultBranchRef.name` で調べる。

# 5. 作業ツリーのクリーン確認

`git status` を叩く。
もし未コミットの変更（未追跡のファイルも含む）があれば、以下を人間に確認する

- レビュー作業はソース変更を伴う
- 既存の変更と混ざるため、コミットしてよいか

上記確認に対する人間の返答に応じて分岐する

- 了承: コミットして続行する。コミットメッセージは変更内容をもとに作成する
- 断られた: 早期終了

## 状況の決め方

- 引数なし: ローカル
- PR番号あり、回数が1: PR1回目
- PR番号あり、回数が2: PR2回目
