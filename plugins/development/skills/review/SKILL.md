# Skillの引数

本Skillが想定している呼び出し方は2通り

```sh
1. /review # 引数なし
2. /review 1234 # PR番号
```

# 手順

1. `references/precheck.md` を読み、手順を最後まで実行する。早期終了になったら、理由を伝えて終わる。
2. 早期終了にならなければ、precheckで決めた状況の資料を下表から選んで読み、「呼び出すもの」を順に呼び出す。

| 状況                          | 呼び出し方            |
| ----------------------------- | --------------------- |
| 引数なし                      | `references/local.md` |
| 引数あり かつ PRレビュー1回目 | `references/pr_1.md`  |
| 引数あり かつ PRレビュー2回目 | `references/pr_2.md`  |

# 実施中の決まり

- レビューSkill, sub agentが実施したソース変更は、その処理が完了した後にコミットする。コミットに人間の承認は挟まず実行してよい。
- コミットの分け方、コミットメッセージは変更内容に応じてClaude側で調整する。
- push, PRのready化は実行しない。
- レビューSkillの`--fix`がスキップした指摘のうち、設計・仕様に関わるものは人間に聞く。
- PRレビューで、独自観点レビューが`レビュー作業: 中断(PR品質基準未達)`を返した場合は、レビューを中断し、`# レビューサマリの投稿（PRのみ）`に移る。
  - ユーザーにはレビューがPR品質が基準未満で中断したことと、`development:split-pr`でPR分割ができる旨を報告する。

# レビューサマリの投稿（PRのみ）

レビューが完了したら、各レビューskill, sub agentからのメインセッションやPR等への出力をもとにレビューサマリを投稿する。
フォーマットは`references/review-summary-format.md`。
レビュー中断はレビュー回数に数えないため、中断して終了した場合は1行目のレビュー回数コメントは記載しない。

# レビュー終了報告

以下をチャットで人間に報告する

- レビュー結果: 完了or中断
  - PR品質レビューでレビューが中断した場合は中断
- レビュー作業中に作成したコミットの一覧を`git log --oneline`の表示と同じ形式でまとめ、報告する。
- pushしていないため、人間側でコミットを確認後、対応してほしい旨
- (PRレビュー2回目のみ)PRのready化をしていないため、人間側でコミットを確認後、対応してほしい旨
